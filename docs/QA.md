# 검증 기록

## 2026-10-21 Gemini AI 기능 추가

- Gemini JSON 응답 처리, 변수 손상·중복·빈 후보 거절, 권한/한도 오류의 비밀값 비노출, 잘린 응답 거절을 포함한 단위 테스트 총 20개 통과.
- 의존성 복구 후 TypeScript 통과. 기존 사이트용 프로덕션 빌드 5단계 통과.
- 후보별 DOM 측정, 명시적 선택 후 재검사와 기존 D1 캐시·요청·한도 테이블 연동을 구현했습니다.
- 실제 Gemini 키 발급·서버 연결·실제 응답 및 최신 영상 촬영은 대기 중입니다. 모의 테스트는 실제 API 성공의 증거가 아닙니다.

## 배포 후 실제 검증

2026-10-13에는 공개 사이트에서 실제 Google 번역을 세 언어에 실행하고 변수 복원, 54조건 UI 검사, 클라우드 저장·새로고침 복원, 보고서 다운로드를 확인했습니다. 단위 테스트 16개와 TypeScript도 재확인했습니다.

2026-10-14에는 새 프로젝트의 두 문구를 실제 Google API로 독일어·프랑스어·한국어에 번역하여 36조건을 검사했습니다. 독일어 버튼을 수정한 뒤 넘침 문제 수가 15개에서 13개로 감소하고 선택한 독일어 버튼의 모든 너비가 통과하는 것을 확인했습니다. 다른 언어와 인사말의 문제는 남아 있습니다. 변수 누락·복구, 보고서 다운로드, 클라우드 저장도 확인했습니다.

제출 점검에서는 공개 주소의 HTTP 200 응답과 실제 배포 D1의 `projects`, `runs` 기록 조회를 확인했습니다. 배포 후 점검에서 과거의 모든 테스트를 반복한 것은 아닙니다.

로컬 모의 로그인 후 클라우드 저장과 다른 브라우저 컨텍스트 복원도 통과했습니다. 프로젝트 이름 변경이 미저장 상태로 표시되는지 확인했습니다.

## 확인한 환경 제약

- 제한된 Windows sandbox에서는 Chrome/Workers 프로세스가 실행되지 않아 승인된 로컬 프로세스로 검증했습니다.
- Wrangler HTTP 프록시 경유에서 큰 프로젝트의 다른 실행 ID 삽입 차단 요청에 연결 재설정이 관찰됐습니다. 같은 빌드를 Miniflare에 직접 dispatch한 결과는 올바른 403이며 DB에 삽입되지 않았습니다. 프록시 경유 테스트는 통과했다고 기록하지 않습니다.
- 빌드된 Worker를 실행한 채 다시 빌드하면 Windows 파일 잠금으로 `EPERM`이 발생합니다. 로컬 Worker를 종료하면 빌드가 통과합니다.
- Sites의 Windows 범용 npm 래퍼는 경로 오류를 냈습니다. 같은 starter의 직접 Node 빌드 명령으로 성공했습니다.

## 범위상 한계

검사 결과는 고정 fixture의 수평 너비에 한정됩니다. 전체 앱 CSS, 다중 줄/세로 넘침, 번역 의미 정확도, 모든 브라우저의 결과 일치를 보장하지 않습니다. 클라우드 동시 편집 충돌은 timestamp 우선이며 협업 병합을 지원하지 않습니다. Google 키 설정만으로 실제 호출이 검증된 것은 아닙니다. 키 연결 후 SETUP.md의 작은 입력 검증을 수행해야 합니다.
