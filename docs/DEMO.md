# 수행평가 시연과 설명

## 약 3분 시연

1. 샘플 프로젝트를 열어 직접 작성한 데모 번역 표시를 설명합니다.
2. **UI 검사 실행**을 누르고 180개 실제 DOM 측정을 보여 줍니다.
3. 독일어 `checkout.buy`의 100px 버튼에서 초과한 실제 px와 추천 너비를 보여 줍니다.
4. 독일어를 `Jetzt kaufen`으로 수정합니다. 이전 검사 안내를 확인하고 다시 검사합니다.
5. 실행 이력에서 같은 조건의 해결 건수를 보여 줍니다. 과거 실행의 입력 스냅샷이 그대로인 것을 설명합니다.
6. `account.greeting`에서 기본/긴 name 값을 바꿔 검사합니다. 문자 길이와 실제 너비가 같지 않다는 점을 설명합니다.
7. `{name}`을 지워 변수 오류를 보여 주고, 정상 문구로 되돌립니다.
8. 매트릭스에서 언어·폰트·너비 조합을 보고 JSON 보고서와 프로젝트 백업을 내보냅니다.
9. 연결된 경우 클라우드 저장/새로고침 복원을 보여 줍니다. Google 키 연결 후에만 실제 번역 버튼과 토큰 복구를 시연합니다.

## 개발자가 설명할 내용

- 번역문을 얻는 일과 UI에 맞는지 판단하는 일은 서로 다른 문제입니다.
- 문자 수 대신 렌더링된 span과 내부 영역 너비를 비교합니다.
- 변수는 번역 전 보호하고 번역 뒤 종류·개수를 재확인합니다.
- 회귀 비교는 동일 조건일 때만 의미가 있습니다. fixture·환경이 달라지면 직접 비교하지 않습니다.
- 클라우드 DB는 프로젝트, 실행, 번역 요청, 캐시, 한도를 저장합니다. 서버가 로그인 사용자를 기준으로 접근을 제한합니다.
- 기존 서비스 아이디어 위에 조건 매트릭스·변수 시뮬레이션·회귀 비교를 결합한 점이 차별 요소입니다.

## 정직한 평가 범위

API 없는 샘플 실행을 Google 성공으로 설명하지 않습니다. 고정 fixture의 수평 넘침 검사이며 전체 웹페이지의 스타일·줄바꿈·세로 레이아웃·번역 의미 품질까지 검증했다고 주장하지 않습니다. 실제 Google 호출 및 실제 호스팅 로그인 증거는 준비 상태와 구분해서 제출합니다.
