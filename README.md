# LocaleBench

## 프로젝트 이름

**LocaleBench(로케일벤치)**

## 프로젝트 소개

**번역한 문구가 버튼과 라벨 안에 잘 들어가는지 확인하는 웹서비스입니다.**

앱을 다른 언어로 번역하면 글자가 길어져 버튼에서 잘릴 수 있습니다. LocaleBench는 원문을 자동 번역하고, 여러 너비와 글꼴에서 실제 표시되는 길이를 측정합니다. Google Gemini 생성형 AI가 짧은 번역 후보를 제안하면 각 후보도 실제로 측정하여 선택·적용하고 수정 전후를 비교합니다.

## 실행 주소

**[LocaleBench 사용하기](https://localebench-ui-lab.almondhawk7.chatgpt.site/)**

공개 배포된 사이트입니다. 샘플 검사와 직접 입력한 번역의 검사는 로그인 없이 사용할 수 있습니다. **Gemini AI 제안, Google 자동 번역, 클라우드 저장**은 사이트의 **ChatGPT 로그인** 후 사용합니다. 주요 사용자는 다국어 웹·앱을 만드는 개발자와 번역 담당자입니다.

## 주요 기능

- **원문 입력:** 영어 문구를 flat JSON 텍스트나 파일로 가져오고 중복 키와 형식을 검사합니다.
- **자동 번역:** 독일어·프랑스어·한국어 중 선택한 언어로 Google 번역을 실행합니다. 번역문을 직접 수정할 수도 있습니다.
- **생성형 AI 문구 제안:** Google Gemini API로 현재 문구의 짧은 후보를 최대 3개 생성합니다. 변수 무결성을 검증한 뒤 각 후보를 현재 너비·글꼴에서 실제 측정하고, 사용자가 선택한 문구만 적용하여 재검사합니다. AI의 설명과 브라우저의 실측 결과를 구분합니다.
- **UI 검사:** 버튼·라벨·한줄 배너에 문구를 넣고 실제 브라우저에서 수평 넘침을 측정합니다. 초과한 길이와 필요한 너비를 표시합니다.
- **검사 매트릭스와 문제 목록:** 너비·글꼴별 결과표와 수정할 문제를 확인합니다.
- **변수 검사:** `{name}`, `{count}`, 단일 `%s`처럼 값이 들어갈 자리의 이름과 개수가 번역에서 유지되는지 검사합니다. 기본 값과 긴 값으로 비교할 수 있습니다.
- **실행 이력:** 당시 문구와 조건을 보관하고 같은 조건의 새 문제·남은 문제·해결한 문제를 비교합니다.
- **저장과 조회:** 브라우저에 자동 저장하며 로그인하면 프로젝트와 검사 이력을 클라우드 DB에 저장하여 다시 불러옵니다.
- **내보내기와 복원:** 번역 JSON·검사 보고서·프로젝트 백업을 내려받고 백업을 새 프로젝트로 복원합니다.
- **검사 설정과 편의 기능:** 글자 크기·내부 여백·너비·이름 변수 값을 설정하고 검색·필터·모바일 메뉴를 사용합니다.

## 처음 사용하는 방법

1. **새 프로젝트**를 만들거나 **샘플 프로젝트 열기**를 누릅니다.
2. 직접 시작하려면 **JSON 가져오기** 입력칸에 아래 예시를 붙여넣고 **문자열 가져오기**를 누릅니다.

   ```json
   {
     "button.start": "Start now",
     "message.hello": "Hello, {name}"
   }
   ```

   왼쪽은 문구 이름표, 오른쪽은 실제 영어 문구입니다.

3. 로그인 후 언어를 선택하고 **Google 번역**을 누릅니다. 필요한 다른 언어도 같은 방식으로 번역합니다. 직접 입력해도 됩니다.
4. **UI 검사 실행**으로 미리보기와 매트릭스를 확인합니다. 모든 대상 언어를 함께 검사하므로 빈 번역문은 측정 실패로 표시될 수 있습니다.
5. 넘치는 문구의 **AI로 짧은 문구 제안**을 누르면 Gemini가 후보를 생성합니다. 후보별 통과 조건과 실제 너비를 확인하고 **이 문구 적용 후 재검사**를 누릅니다. 직접 수정해도 됩니다. AI가 줄인 문구의 의미는 사람이 확인합니다.
6. 실행 이력에서 수정 전후를 비교하고 필요한 파일을 내보냅니다.

## Google API

### Google Gemini API — 생성형 AI

서버가 선택한 문구의 영어 원문, 현재 번역문, 대상 언어, 컴포넌트와 검사 조건을 **Gemini API**에 전달합니다. 모델이 새 번역 후보와 짧은 설명을 JSON으로 생성합니다. 한국어 설명을 요청하지만 실제 출력 언어는 모델 응답에 따라 달라질 수 있습니다. 서버가 변수 이름·개수를 검사하고 중복·빈 후보를 제외합니다. 화면은 반환된 후보를 실제 DOM으로 측정하여 조건별 통과 여부를 보여줍니다. AI가 픽셀 적합성을 판정하지 않습니다.

기본 모델은 `gemini-3.5-flash-lite`이며 서버의 `GEMINI_MODEL`로 변경할 수 있습니다. 키는 비공개 환경변수 `GEMINI_API_KEY`에만 저장합니다. 로그인·프로젝트 소유권을 확인하고 사용자당 하루 20회, 앱 전체 100회의 요청 예약 한도를 적용합니다. 같은 입력의 AI 결과는 사용자별 DB 캐시로 재사용하며, 실패한 요청도 예약량에 포함합니다.

2026-10-22 실제 Gemini API 응답과 배포 사이트의 후보별 DOM 측정을 확인했습니다. 생성된 `Starten`을 선택하여 재검사하자 해당 버튼의 6조건이 모두 통과했고 전체 넘침이 15건에서 13건으로 줄었습니다. D1 저장과 새로고침 후 조회도 확인했습니다. AI가 생성한 후보가 반드시 화면에 맞는 것은 아니므로, 후보별 통과 조건을 확인한 뒤 적용합니다. 변수 누락·빈 응답·중복 후보와 명백한 대상 언어 혼동을 걸러내며, 번역 의미의 최종 판단은 사용자가 합니다.

### Google Cloud Translation API — 자동 번역

**Google Cloud Translation API의 Basic v2**를 사용합니다. 서버가 영어 원문과 대상 언어를 Google에 전달하고, API가 반환한 번역문을 편집칸에 채웁니다. 이 응답으로 실제 UI 검사를 실행합니다.

번역 중 변수를 보호하고 응답에서 복원합니다. 중복 요청을 제어하고 동일 입력의 번역 캐시를 저장하며, 사용자별·앱 전체의 일일 문자 예약 한도를 적용합니다.

API 키는 서버의 비밀 환경변수 `GOOGLE_TRANSLATION_API_KEY`로 관리하며 GitHub·프론트엔드·원문 JSON에 넣지 않습니다. 배포 사이트의 실제 독일어·프랑스어·한국어 번역은 2026-10-13 및 2026-10-14 시연에서 확인했습니다. 샘플 번역은 별도로 준비한 연습용 데이터입니다.

## 데이터베이스

클라우드 DB는 **Cloudflare D1(SQLite)**입니다. 로그인한 사용자별로 저장·조회하며 다른 사용자의 프로젝트에 접근하지 못하도록 검사합니다.

| 테이블 | 저장하는 데이터 |
|---|---|
| `projects` | 프로젝트 이름, 원문·번역문, 검사 조건, 수정 상태 |
| `runs` | 검사 시각, 당시 문구와 조건, 실제 측정 결과 |
| `translation_cache` | 번역 결과와 Gemini AI 후보·모델·설명 캐시. AI 키는 `gemini:` 접두사로 구분 |
| `translation_requests` | 번역 및 Gemini 요청의 중복 방지와 처리 상태 |
| `quota` | 일일 번역 문자 예약량과 별도로 구분된 AI 요청 횟수 |

프로젝트 API가 DB에 저장하고, 사이트를 열 때 사용자의 프로젝트와 최근 검사 이력을 조회합니다. 로그인 없이도 사용할 수 있도록 **IndexedDB** 브라우저 저장을 함께 제공합니다. 로컬 개발 DB와 배포 DB는 별개입니다.

## 로컬 실행

Node.js 24 환경에서 프로젝트 폴더를 열고 실행합니다.

```sh
npm run install:ci
npm run build
npm run db:local
npm run dev -- --host 127.0.0.1 --port 5173
```

로컬 주소는 `http://127.0.0.1:5173`입니다. `db:local`은 빈 로컬 DB의 첫 초기화에만 사용합니다. 로컬 로그인은 개발용 모의 계정이고 공개 사이트는 실제 ChatGPT 로그인을 사용합니다.

별도 환경에서 자동 번역을 실행하려면 `.env.example`을 참고하여 Git에서 제외되는 `.env.local` 또는 호스팅 서버의 비밀 환경변수를 설정합니다. 배포 서비스의 실제 키는 소스에 포함되지 않습니다.

## 검증 기록

- 개발 단계: 단위 테스트 16개, 브라우저 시나리오 8개, Worker+D1 통합 시나리오 1개, TypeScript, ESLint, 프로덕션 빌드 통과.
- 2026-10-21~22 AI 확장: 단위 테스트 21개, 브라우저 시나리오 10개, Worker+D1 통합 시나리오 1개, TypeScript와 프로덕션 빌드 통과. 브라우저 자동 테스트의 Gemini 응답은 모의 데이터이며, 별도로 실제 Google Gemini 호출과 공개 배포 사이트의 후보 생성·실측을 확인했습니다.
- 2026-10-13 배포 점검: 실제 Google 번역·변수 복원·54조건 검사·클라우드 저장·새로고침 복원·보고서 다운로드 확인. 단위 테스트와 TypeScript 재확인.
- 2026-10-14 발표 시연: 두 문구를 세 언어로 자동 번역하고 36조건 검사. 독일어 버튼 수정으로 문제 수가 15개에서 13개로 감소하는 것을 확인. 변수 누락·복구, 보고서 다운로드, 클라우드 저장 확인.
- 2026-10-14 제출 점검: 공개 서비스 HTTP 200과 실제 D1 프로젝트·검사 기록 조회 확인.

문제 수는 발견한 문구의 넘침을 뜻하며 서비스 장애 수가 아닙니다. 마지막 점검에서 모든 기존 테스트를 다시 실행한 것은 아닙니다. GitHub Actions 워크플로는 `.github/workflows/ci.yml`에 있으며 외부 CI 결과는 실제 실행 결과로 확인합니다.

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm run test:worker
npm run test:browser
```

브라우저 테스트에는 실행 중인 개발 서버가 필요합니다.
